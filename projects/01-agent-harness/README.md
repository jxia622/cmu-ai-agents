# Project 1 · Build an Agent Harness

**A course project for Carnegie Mellon University 11-768: AI Agents, Language Technologies Institute, School of Computer Science.**

This project implements a shared ReAct agent harness and applies it to two environments: a coding agent that repairs a chess application, and a chess agent that interacts with the repaired application. It also implements context compaction, reusable skills, and programmatic tool calling through a remote Python sandbox.

## My implementation

The implementation builds on the [CMU Assignment 1 starter](https://github.com/cmu-agents/assignment-1). My changes are in these five files:

| File | Work implemented |
| --- | --- |
| [`agent/base.py`](src/assignment/agent/base.py) | Prompt and history construction, shared ReAct loop, step limits, skill discovery and YAML validation, and model-generated context compaction that preserves recent complete tool interactions. |
| [`agent/code_agent.py`](src/assignment/agent/code_agent.py) | Coding prompts, terminal execution, completion signaling, skill invocation, and recoverable tool-call errors. |
| [`agent/tools.py`](src/assignment/agent/tools.py) | Tool schemas for chess moves, simulation, sandboxed Python execution, and skill invocation. |
| [`agent/chess_agent.py`](src/assignment/agent/chess_agent.py) | Chess tool dispatch, board-state updates, terminal-state handling, and state refresh after programmatic actions. |
| [`agent/chess_tools.py`](src/assignment/agent/chess_tools.py) | Chess API requests, stateless move simulation, sandboxed Python execution, and recoverable chess errors. |

The course provides the surrounding sandbox infrastructure, runners, evaluation tasks, tests, and chess application. The original assignment specification is preserved in [`ASSIGNMENT.md`](ASSIGNMENT.md), and the original starter README is preserved in [`STARTER_README.md`](STARTER_README.md).

## How it works

```text
Task + standing instructions
          |
          v
Shared ReAct loop <--- tool observations / working memory
          |
          +--> CodeAgent --> Modal terminal --> generated repair patch
          |
          +--> ChessAgent --> chess API --> board state and moves
                          --> Python sandbox --> simulation and move selection
```

The agents expose skill metadata in the prompt and load complete instructions through `invoke_skill`. When the configured context threshold is reached, the shared harness summarizes older interactions into working memory while keeping the original instructions and recent tool interactions.

## Setup

Requirements: Python 3.11+, Git, and [uv](https://docs.astral.sh/uv/).

From this project directory:

```bash
make setup
make test
```

The chess application is a Git submodule pinned to the task's original base commit. `make setup` initializes it and verifies that the source matches the expected commit.

To run agents, configure your own model endpoint and credentials:

```bash
cp .env.example .env
# Edit .env with your OpenAI-compatible endpoint, API key, and model.
uv run modal setup
make doctor
```

Agent runs and Modal integration tests use paid model and cloud resources. The default `make test` suite is offline.

Examples:

```bash
# Coding agent: generate a repair patch
make run-code-agent

# Replay the patch in a fresh Modal testbed
make check-part1

# Play chess using the repair patch
make run-chess-agent

# Enable Python tool calling and the supplied chess skill
uv run assignment-play-chess --programmatic-tools \
  --skills-path tasks/chess-skills \
  --trajectory artifacts/part3-python-skill-trajectory.json
```

The supplied [`artifacts/fix.patch`](artifacts/fix.patch) prevents the chess application from requesting a bot reply after a human move has already ended the game. It was generated by the coding agent; the pinned chess submodule retains the original task state.

## Validation and available results

On October 3, 2026, the supplied offline assignment suite passed: **15 passed, 4 deselected**. The four deselected tests launch real Modal sandboxes and are excluded by the default pytest configuration.

The compact [`artifacts/run-summary.json`](artifacts/run-summary.json) records counts extracted from the existing local trajectories:

| Saved run | Model responses | Evidence |
| --- | ---: | --- |
| Coding agent | 14 | 17 terminal calls, one skill invocation, and one completion call; generated repair patch included. |
| Basic chess agent | 49 | 49 direct `play_move` calls. |
| Chess with Python and skill | 12 | One skill invocation, 10 `run_python` calls, and one direct `play_move` call. The saved Python snippets call both `simulate_move` and `play_move`. |
| DeepSeek, legal moves included | 75 | 74 direct move calls; the associated saved result reports a terminal draw. |
| DeepSeek, legal moves omitted | 33 | 33 direct move calls; the associated saved result reports a terminal White win. |

These are observations from individual saved runs, rather than aggregate model performance claims. Large raw trajectories remain local; the repository includes the compact summary and repair patch.

### Evidence limitations

Context compaction is implemented and covered by the available offline tests, but the local artifacts do not include the requested SWE-bench patch, compacted and baseline trajectories, or token-usage analysis. The two GPT-OSS observation-experiment logs contain zero model responses, with no corresponding result files. The full four-run A/B experiment and its analysis therefore cannot be reported as complete from the available files. No new cloud evaluation was run when preparing this portfolio.
